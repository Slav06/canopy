# Wholesale pipeline and property views

Leads opens as a tile board, retaining Table view and search/status filters. Stages run from New through contact, follow-up, qualification, appointments, offers, contract, marketing to buyers, assignment, closing and closed, plus Dead. Existing statuses and records are preserved. Moving a tile writes the existing authenticated lead PATCH route, records the transition in activity history and refreshes from saved server state. Stage changes do not execute contracts, create financial records, synchronize deal stages or record payments.

Admin and Upper Management with Edit leads enabled can drag tiles between columns. Every tile also has a keyboard/touch accessible stage selector. Basic Agents see assigned leads and can open them, without move controls; server restrictions also reject their stage changes. Only Admin retains delete/restore access.

Every lead detail, including Calling, includes Satellite, Map and Street View tabs. Address-based Google map embeds work without credentials; imagery is fetched from Google, not stored in CRM. Demo addresses are fictional and may resolve to approximate locations. Verify Google's location against the actual property. No Street View photo is fabricated or treated as verified property imagery.

Automatic street imagery now uses **Mapillary**, not Google Street View Static API. Opening a lead checks its full US address using the US Census geocoder, then searches Mapillary within a 65m bounding box and selects the nearest available returned capture within 60m. Ambiguous/unmatched addresses do not select imagery. The limited search returns at most 100 candidate captures; no coverage result means no suitable capture was found in that response, not proof of zero provider coverage. Nearby imagery may show adjacent properties. The UI shows distance, capture date, author attribution, and a link to Mapillary. Mapillary imagery is not necessarily panoramic. Satellite/Map tabs remain Google no-key map embeds.

No Google billing or key is needed. One-time setup: sign in/create a free Mapillary account, register a read-only application in https://www.mapillary.com/dashboard/developers , set its client token as `MAPILLARY_CLIENT_TOKEN` in the CRM server environment (locally `.env.local`), and restart. Do not use the client secret or grant write/upload scopes. Token is server-only; no token is returned by the CRM or included in provider query URLs. No per-property link is required. Missing token, address problems, unavailable coverage, provider errors and failed images have a satellite fallback. No paid Google photo calls remain. Google billing signup is unnecessary for this integration.

Street imagery and lookup metadata are not persisted. Only HTTPS Mapillary/Facebook image CDN URLs returned by the authorized provider are displayed, with attribution. Access is checked against assigned leads/view-all permission before external lookups. The free integration relies on third-party coverage and availability; live lookup requires completing the Mapillary account/token step. US Census coordinates are approximate and should be checked against the actual property.

Tests additionally cover nearest-capture radius, image URL safety, missing-token no-network behavior, ambiguity rejection, token non-disclosure and attribution. Provider replies are mocked in tests; no Mapillary token was available for a live lookup during implementation.

Validation: production build, TypeScript, 17 unit/security checks, 33 role acceptance checks, persistence of all 12 stages, invalid-stage/embed rejection, Basic Agent map/stage restrictions, real browser drag/drop and restore using a demo lead, and Google satellite iframe rendering. Local test fixtures restored; no calls or external form submissions occurred.
